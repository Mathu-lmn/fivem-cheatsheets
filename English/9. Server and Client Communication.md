# Server and Client Communication

FiveM scripts are divided between two types of scopes: **Client** script and **Server** script. 
- *Client:* Everything running on the player's game instance (UI, 3D world, keys).
- *Server:* Global logic for all players (database access, global sync, security).

Communication between these scopes uses events via `TriggerServerEvent` and `TriggerClientEvent`.

## Triggering from Client to Server
```lua
-- In Client-side script:
TriggerServerEvent("myScript:giveItem", "water", 1)

-- In Server-side script:
RegisterNetEvent("myScript:giveItem", function(itemName, count)
    -- Security check: You can get the player ID who triggered the event using `source`
    local playerId = source
    print("Player " .. playerId .. " wants " .. count .. "x " .. itemName)
    -- Perform inventory addition here safely on the server
end)
```

## Triggering from Server to Client
```lua
-- In Server-side script:
local playerId = 1 -- Example player ID to send the event to
TriggerClientEvent("myScript:showNotification", playerId, "Welcome to the server!")

-- Or trigger to all players:
TriggerClientEvent("myScript:showNotification", -1, "Server is rebooting soon.")

-- In Client-side script:
RegisterNetEvent("myScript:showNotification", function(message)
    -- Display notification natively for the player
    BeginTextCommandThefeedPost("STRING")
    AddTextComponentSubstringPlayerName(message)
    EndTextCommandThefeedPostTicker(false, false)
end)
```
**Important**: You can combine `RegisterNetEvent` and the callback function into one call, which makes the code cleaner.
